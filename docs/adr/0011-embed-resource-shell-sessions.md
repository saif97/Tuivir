# Embed Resource Shell Sessions in Details

Status: accepted; supersedes ADR 0009 and its Interactive Shell handover clauses in ADR 0010

Tuivir will run a Resource's provider-declared exec shell in a private pseudo-terminal and present it through a Shell Detail View Tab rather than hand the whole outer terminal to the Provider CLI. One explicitly started Resource Shell Session may run per Resource, continues while hidden, and can move between the Details pane and an enlarged view without restarting. The Provider still owns shell availability and its explicit program and arguments; Tuivir does not treat Docker-style attachment to a Resource's primary process as a shell.

The application owns the session's Resource identity and user-visible lifecycle while a host-owned runtime owns its child process, pseudo-terminal, terminal engine, input/output, bounded in-memory scrollback, and resize work. The runtime must drain hidden output without requesting hidden redraws and report lifecycle changes through application events. Selecting an unused Shell tab does not start work: Enter starts it in Details, while `E` starts or resumes it enlarged. Terminal focus sends keyboard and mouse input to the session; a configurable `Ctrl-B` prefix uses `q` to release focus and `z` to toggle enlargement, while clicking outside the terminal returns focus to Tuivir. The first version has no separate manager or indicators for hidden sessions; returning to a Resource's Shell tab resumes its session.

A normal shell exit retains its final screen as `Session exited`; Enter replaces it with a fresh session. A stopped Resource may therefore retain an exited screen, while confirmed Resource deletion removes it. Tuivir keeps at most 10,000 scrollback lines per session in memory, never persists them by default, and ignores terminal-originated clipboard writes. Ordinary application Quit confirms before terminating live sessions; there is no separate shell-close command or terminal-mode emergency-Quit chord.

Tuivir selects `alacritty_terminal`, using its platform PTY and event loop behind a Tuivir-owned Ratatui cell adapter. An isolated Cargo-only harness successfully ran local and Docker shell smoke tests and rendered `btop`; the candidate avoids Ghostty's Zig-native build, C ABI/community binding, pinned source distribution, and unstable API maintenance. The originally proposed Ghostty harness is deliberately waived rather than claimed complete. The Resource Shell Session implementation must still complete the Alacritty acceptance script with Neovim, `btop`, local and Docker shells, alternate screens, colors, Unicode graphemes, cursor and keyboard modes, bracketed paste, mouse reporting, terminal replies, repeated resizing, hidden output draining, and clean restart after exit. A concrete Alacritty fidelity failure reopens the Ghostty evaluation. Inline graphics and hyperlinks are outside the first version because Ratatui's cell buffer cannot faithfully present them inside the Details pane.

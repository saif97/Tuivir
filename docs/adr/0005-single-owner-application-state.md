# Keep application state single-owned

Virtui's main event loop will exclusively own and mutate plain `AppState`, including the active `ProviderId` and the set of pending provider requests. Provider work, terminal input, and timers publish results as events rather than sharing `AppState` through locks. Every background request has a unique `ProviderRequestId` and an explicit target containing its `ProviderId` and, for detail work, its `ResourceId` and `DetailViewId`. Switching providers invalidates requests for the previous provider, and changing selection invalidates detail requests for the previous target; a completion is accepted only while its request ID remains pending for the current target. Rendering reads the state without performing I/O. This keeps concurrency out of the domain state and allows navigation, refresh, and provider-switching behavior to be tested without a terminal or installed provider CLI.

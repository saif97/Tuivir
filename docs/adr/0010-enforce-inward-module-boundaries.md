# Enforce inward module boundaries

Virtui will expose four architectural modules: `domain`, `application`, `presentation`, and `infrastructure`. Dependencies point inward. Domain owns provider-neutral identity and vocabulary and imports no other layer. Application owns Commands, logical Keys, events, requests, state transitions, `ProviderWorkspaceState`, and read-only workspace projections, and depends only on domain. Presentation translates Crossterm events into logical Keys and renders immutable application state and views; it neither mutates `App` nor executes work. Infrastructure owns configuration and process adapters, Provider Workspace adapters, discovery, refresh timing, and asynchronous request execution; it may publish specific `AppEvent` values but never receives `AppState`. Presentation and infrastructure do not depend on one another.

`main.rs` remains the composition root and host rather than becoming a fifth layer. It wires the concrete adapters, exclusively owns `App`, runs the terminal event loop, dispatches returned `ProviderRequest` values, and coordinates Interactive Shell terminal handover. Terminal handover therefore stays testable at a private host seam in the binary while provider request execution remains infrastructure. The Provider Workspace adapter contract also stays in infrastructure: application owns the data crossing that boundary, not an abstract provider port it does not need.

The domain `Provider` is the single record of provider identity and descriptive metadata: id, name, Target Environment, and optional Provider Version. Infrastructure `ProviderDiscovery` wraps that record with discovery failure evidence, while application `ProviderWorkspaceState` wraps it with load and navigation state. This avoids parallel objects that can drift. Process errors likewise stop at infrastructure; Interactive Shell handover crosses the application boundary as an application-owned process description and returns an application-owned outcome.

Command and keybinding policy stays in application through `CommandRegistry` and `KeybindingError`. Infrastructure configuration code selects and reads files, parses TOML, and delegates validation to that policy. Temporary top-level compatibility modules are permitted only while moving a seam and are removed once callers use the canonical module path.
